{%- comment -%}
  Product page (product_screen.dart). Contained gallery with thumbnails, brand / name / price, exact-variant choice,
  availability, quantity, the real Shopify product form, other ways to buy, accordions and app blocks (Loox and the like).

  Everything commercial is rendered by Shopify at request time: price, compare-at, availability, options, the selected variant.
  When the shopper changes an option, assets/monetta-product.js asks the Section Rendering API for this same section with
  ?variant=ID and swaps the [data-product-dynamic] and [data-purchase-dock] regions, so no price or stock is ever cached or
  recomputed in the browser. The add button posts the exact variant id and never substitutes another: while a choice has not been
  confirmed by Shopify (or its confirmation failed) adding and the accelerated checkout are blocked, and a failed confirmation puts
  the chips back on the variant the page really shows.

  Without JavaScript the chips are plain links to ?variant=ID, so choosing an option is a navigation and the form always sends the
  variant the page shows. monetta-product.js swaps them for the radio group (html.mw-variants-js) because it can confirm each choice
  without a reload.
{%- endcomment -%}
