## Implemented locally

- `CustomerGraphqlClient`: public endpoint discovery cache only, raw Shopify access-token auth, bounded responses/timeouts, sanitized errors. No private response/token cache. Address writes single attempt; unknown write outcomes carry `CustomerDataException.mutationMayHaveSucceeded` and must be reconciled by reading the provider before retry.
- `ShopifyCustomerAddressService`: paged list/default ID, create/update/delete with actual provider acknowledgments. Payload names are `territoryCode`, `zoneCode`, `phoneNumber`. Nonempty `CustomerAddressInput` fields are allowlisted. Provider validation/permission failure is never an empty success. No local PII persistence or new schema/migration.
- `ShopifyCustomerOrderDetailsService`: separate authorized read, full line-item and fulfillment connection pagination, exact returned-resource ID validation, historical order address, historical line name/quantity/variant ID/title/SKU/order image and provider price/total. Missing optional images/variant/address/money stay null. Shipping status/tracking are independent of financial status. Unsafe tracking URLs are omitted. A changed `updatedAt` while paginating fails rather than mixing snapshots. No order-wide delivered stage or percentage is inferred; consumers must keep partial/canceled/unknown distinct. Per-shipment line allocation is not part of this initial DTO.
- `ShopPolicyRepository`: existing merchant Storefront policies, semantic kind + ID/title/bodyHtml/url, unavailable when unpublished/empty, provider failure throws. Body is merchant content, never generated legal/benefit text. Consumers must render it using an appropriate safe reader.
- `AccountReadScope<T>`: session-local optional read value; account change/sign-out/clear invalidates it. Late prior-session and superseded same-session reads cannot overwrite a newer value. It is an application integration helper, not an authorization authority.
- Rewards: required cents/time in summary and ledger activity no longer become fabricated zero/now on malformed payloads; old valid V1 responses without new optional capabilities still parse. Activity preserves provider cursor and rejects malformed rows. Summary/activity/order reads reject missing auth and stale token/session responses. `RewardsApi.clearSession()` invalidates A→B→A late reads. Server adds versioned unsupported membership/progress/benefits capabilities; `RewardsSummary.membershipAvailable`, `tierProgressAvailable`, `tierBenefitsAvailable` all remain false until an approved source/DTO exists. No earning/redemption/business rules changed.
- Notifications: versioned config explicitly marks exact-variant restock and account-wide unread unavailable. Variant/email request bodies rejected before subscription/consent, old generic device product alerts retain existing semantics. `NotificationController.variantRestockAvailable` is false; legacy createRestockAlert returns false without requesting permissions, changing preferences or sending a subscription. A08 must hide G12 from this gate.
- Producer: only actual Admin options/image are emitted. Existing DTO source fields optional, old fixtures remain valid; output `{}`/`[]` for missing metadata, no parsing titles or copying product images. No Flutter product mapping/cache/codegen edited.
