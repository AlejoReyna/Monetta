## Acceptance criteria for the first set

**Panels:** menu enters from its edge, filters retain their current right drawer unless the exploratory phone sheet is separately approved, and search makes its field immediately available. Animate panel transform for 280ms and scrim opacity for 180ms. Closing during opening reverses from the current rendered position. A stale close timer cannot dismiss a reopened panel. Escape and backdrop follow one close lifecycle; focus stays in the modal and returns once to its actual opener after dismissal. Background scroll locking causes no horizontal jump. Preference changes during motion settle safely; reduced motion opens/closes immediately. Native dialog semantics remain intact. Rebinding after a Shopify section reload must not duplicate listeners.

**Purchase feedback:** one accepted input creates one pending operation; repeated taps or Enter do not duplicate it. Keep the existing server response, mutation queue and checkout lock authoritative. Show pending text immediately, preserve the selected variant and restore retry affordances after a known failure. Do not promise failure when a network interruption leaves the operation uncertain: retain the current reconciliation behavior and message in `monetta-cart.js:251`. Animate a small success/count accent only after authoritative cart rendering. Counts and money change directly to confirmed values; never roll through invented totals.

The current storefront and app both use an **“En tu bolsa” confirmation surface** (`monetta-cart.js:132`; app `lib/features/checkout/mini_cart.dart:14`). Keep that as the initial implementation. The lab’s inline confirmation is an alternative for evaluating a different interruption level, not another layer to add alongside a drawer and toast. Choose one primary success treatment. Keep errors static, persistent and announced; do not replay decorative success motion on render-only refreshes. Quantity failure restores confirmed state and preserves a usable, visible focus target after section replacement.

**Cards and saved products:** the whole activation area remains fixed. Mouse hover and keyboard focus receive equivalent, subtle image response; no hidden information depends on hover. Touch has an immediate pressed indication and does not wait for animation before navigating. Scrolling or cancelled touch clears that indication. Favor the restrained 1.015 image scale over the expressive 1.045 comparator only if image clarity survives review. Otherwise retain static focus/pressed states. Preserve native link semantics and the separate save control, with at least the shared 48px target. Saved state uses label plus fill/check, updates immediately, and honestly describes browser-local persistence. Reduced motion keeps state and focus while removing scaling.

**Disclosure:** retain `details/summary`, meaningful headings and Playfair section-label typography. Enter/Space and pointer input expose content immediately; only the chevron rotates for 180ms. Rapid toggles reverse cleanly. Closed content is absent from keyboard navigation. Long labels wrap, focus remains visible, and no height animation destabilizes neighboring controls. It must work with JavaScript disabled.

## Preserve the gallery; evaluate alternatives separately

The current gallery already uses scroll snap, thumbnails, keyboard arrows, resize correction and reduced-motion `auto` scrolling: `assets/monetta-product.js:22`; structure `sections/monetta-product.liquid:89`; styling `assets/monetta-pages.css:524`. **Keep that native gallery first.** Browser smooth-scroll timing is browser controlled; it is not a verified 280ms transition. Regression-check gestures, interrupted scrolling and resizing rather than replacing it for token uniformity.

Variant confirmation already aborts previous requests and ignores stale responses (`monetta-product.js:192`), then replaces server-rendered regions and restores option focus (`:224`). Preserve those safeguards. The lab’s 280ms decoded-image crossfade is **exploratory**: its silhouette samples are not real variants, and its immediate illustrative price update must not replace production Shopify validation. Any future crossfade should preserve the native gallery, reserve dimensions, handle decode failure, and act only after the latest confirmed selection. Allow 1–2 design hours, 4–8 engineering hours and 4–6 QA hours for a separate experiment before deciding.

## Static, rejected and deferred choices

- **Static first:** headings, prices, availability, errors, product grids, empty states and desktop purchase panel. Use a stable loading ground and readable pending label; no shimmer is required.
- **Persistent mobile purchase dock first:** current `sections/monetta-product.liquid:313` and `assets/monetta-components.css:1911` already provide one. The app’s `lib/features/product/purchase_dock.dart:18` is also persistent. The lab’s contextual entrance is a lower-priority exploration, deferred until overlap, keyboard and discoverability evidence show a need. Its observer/focus logic is not production-ready merely because the lab works. An evaluation would add approximately 0.5 design day, 1 engineering day and 0.5–1 QA day.
- **Reject for this set:** app-style full-width brand flights, overshoot/bounce, flying products, confetti, rolling cart digits, animated money, startup gates, per-card entrance cascades and persistent decorative loops. These add distraction or delay with little orientation benefit.
- **Defer:** editorial reveal, automatic testimonials, scroll morphing headers and page transitions. The app includes 720/920/1100/1320ms sequences, but those are not reasons to extend the shared web tokens. Any optional editorial experiment must leave text readable and avoid hiding the hero/LCP candidate. Retain ordinary document navigation; cross-document transitions would require separate compatibility and Shopify lifecycle investigation.

## Release criteria for a later authorized implementation

At 320, 390, 768 and 1440px, check visible focus, long names, 200% zoom, reduced motion, failed/stalled actions, rapid input, mid-transition reversal and section replacement. Test current iOS Safari, Android Chrome and desktop Safari/Chrome on actual target devices; this lab does not establish those results. Compare the same routes before/after for layout shifts, paint/compositing work and responsiveness under CPU/network constraints. Confirm no essential content depends on animation initialization. Classify inherited Theme Check issues separately. Publishing requires a later, explicit scope.

**Mobile:** panels, clear pending states, native gallery controls and a persistent purchase dock deliver the most value; touch feedback stays brief. **Desktop:** restrained hover/focus response, a side confirmation drawer and static adjacent purchase information fit best. **Shared:** truthful feedback, immediate selection, native disclosure, stable media dimensions, keyboard access and complete reduced-motion alternatives should be consistent across both.
